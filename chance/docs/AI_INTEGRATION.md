# AI integration contract

This document describes the boundary through which a future host application
(Orbis) can supply AI assistance to Orbis Chance.

It documents **only what is implemented in this repository**. No part of the
connection has been tested against Orbis internals, because this repository has
no access to them. Nothing here should be read as a description of how Orbis
works.

Contract version: **1.0.0** (`AI_CONTRACT_VERSION` in `src/ai/contract.ts`).

---

## 1. What exists today

| File | Contents |
|---|---|
| `src/ai/contract.ts` | Typed request and response shapes, the capability list, the `AiAdapter` interface, and version compatibility. |
| `src/ai/registry.ts` | Registration, status reporting and request dispatch. Returns a typed failure when no adapter is registered. |
| `src/app/shared/ToolShell.tsx` | `AiAssistPanel` — the unavailable state shown in every tool, with the manual alternative. |

What these files deliberately **do not** contain, and must not acquire:

- any AI provider client (no Groq client, no Mistral client, no other);
- any API key, or any code that reads one from storage, the environment or a
  configuration file;
- any network call of any kind;
- any assumption about which provider a host uses;
- any invented Orbis API, endpoint or method name.

You can verify this. The following search returns nothing in `src/`:

```bash
grep -rniE 'api[_-]?key|groq|mistral|openai|anthropic|bearer |fetch\(|XMLHttpRequest' src/
```

The only network-capable API the application uses anywhere is `URL.createObjectURL`
for file downloads, which does not leave the browser.

## 2. Capabilities

Nine capabilities are defined. A host may implement any subset; the application
asks which are available and shows the rest as unavailable.

| Capability | What a host would provide |
|---|---|
| `interpretQuestion` | Turn a question in plain language into a structured problem: which tool, which quantities, what is being asked. |
| `suggestMethod` | Recommend a method from the list the application supplies, with reasoning and required assumptions. |
| `identifyMissingInputs` | Name the quantities still needed before a question can be answered. |
| `draftAssumptions` | Draft assumptions for the user to review and edit. |
| `explainResult` | Describe what an already-computed result means in context. |
| `buildScenario` | Propose variables, distributions and relationships as a starting point. |
| `suggestFollowUps` | Propose further questions worth investigating. |
| `explainUncertainty` | Discuss how much confidence a result supports. |
| `interpretStatistics` | Explain what a p-value, interval or effect size does and does not say. |

Each capability also carries a **manual alternative** (`AI_CAPABILITY_INFO`),
shown to the user while AI is unavailable, so no task is blocked on it.

## 3. The adapter interface

```ts
interface AiAdapter {
  readonly contractVersion: string;   // e.g. '1.0.0'
  readonly hostName: string;          // shown in the interface
  capabilities(): readonly AiCapability[];
  request<C extends AiCapability>(
    request: Extract<AiRequest, { capability: C }>,
    signal: AbortSignal,
  ): Promise<AiResult<C>>;
}
```

The host registers it once at start-up:

```ts
import { registerAiAdapter } from 'orbis-chance/src/ai/registry';

const outcome = registerAiAdapter(myOrbisAdapter);
if (!outcome.ok) console.warn(outcome.message);
```

`registerAiAdapter` rejects an adapter that is missing a required method,
declares an unknown capability, or implements an incompatible contract version.
Passing `null` removes the adapter and returns the application to standalone
mode.

### Version compatibility

`isContractCompatible` accepts an adapter whose **major version matches** and
whose **minor version is at or below** this build's. An adapter built against
1.0.0 works with application versions 1.0.x and 1.1.x; one built against 2.0.0
does not.

## 4. Request and response shapes

Every request carries:

```ts
interface AiRequestBase {
  capability: AiCapability;
  contractVersion: string;
  requestId: string;        // generated by the application
  context?: AiContext;      // tool id, sanitised config summary, variable names
}
```

`AiContext` deliberately carries **names and types, never data**. Imported
datasets are never placed in a request: `availableVariables` lists each
variable's name, kind and unit, with no values.

Responses are discriminated unions:

```ts
type AiResult<C> =
  | { ok: true;  capability: C; requestId: string; value: AiResponseMap[C]; provenance?: { model?: string; host?: string } }
  | { ok: false; capability: C; requestId: string; error: AiError };
```

### Error codes

| Code | Meaning |
|---|---|
| `unavailable` | No adapter is registered. Returned by the application itself. |
| `unsupported-capability` | The adapter does not implement this capability. |
| `unsupported-contract-version` | Version mismatch. |
| `cancelled` | The user cancelled; the signal was aborted. |
| `timeout` | The host timed out. |
| `rate-limited` | The host declined for rate reasons. |
| `invalid-request` | The host could not parse the request. |
| `host-error` | Anything else. Set `retryable` when a retry may succeed. |

A host should prefer returning `{ ok: false, error }` over throwing. If it does
throw, `requestAi` converts the throw into a `host-error` result, and an aborted
signal into `cancelled`, so callers always have something honest to show.

### Cancellation

`request` receives an `AbortSignal`. When the user cancels, the application
aborts it; the adapter must stop work and either reject or resolve with
`cancelled`.

## 5. The rule that protects the mathematics

**AI output is a suggestion about what to compute. It is never a computed
result.**

This is enforced by the shape of the contract, not only by convention: no
response type in `AiResponseMap` contains a probability, an expected value, a
quantile, a p-value or any other quantity the application would display as a
result. A host *cannot* return a number that the application will present as an
answer.

What a host can return is a *model*: a suggested tool, a configuration
fragment, a distribution choice. The application then:

1. validates it with the same validation every manual input passes
   (`validateScenario`, `validateParams`, `validateRequest`, …);
2. rejects it with a message if it is invalid;
3. computes the result with the deterministic or statistical engine.

The mathematical engine (`src/engine/`) imports nothing from `src/ai/`. That
dependency direction is one-way and should stay that way.

## 6. How to test an integration

A host can be exercised without any provider by registering a stub:

```ts
import { registerAiAdapter } from './src/ai/registry';

registerAiAdapter({
  contractVersion: '1.0.0',
  hostName: 'Test host',
  capabilities: () => ['suggestMethod'],
  async request(req) {
    if (req.capability !== 'suggestMethod') throw new Error('unreachable');
    return {
      ok: true,
      capability: 'suggestMethod',
      requestId: req.requestId,
      value: {
        // Must be an id from req.availableMethods.
        methodId: req.availableMethods[0].id,
        reasoning: 'Chosen for the test.',
        requiredAssumptions: ['Trials are independent.'],
      },
    };
  },
});
```

Checks worth making against a real adapter:

- registering an adapter with an incompatible `contractVersion` is refused;
- a declared capability that the adapter does not actually handle returns
  `unsupported-capability` rather than hanging;
- aborting the signal mid-request resolves or rejects promptly;
- a `suggestMethod` response naming a method id **not** in
  `availableMethods` is rejected by the caller rather than acted on;
- a `buildScenario` response that fails `validateScenario` surfaces the
  validation messages instead of running.

## 7. What changes for users after integration

**Becomes available:** the nine capabilities above, as assistance around the
tools — interpreting a question, suggesting a method, drafting assumptions,
explaining a result in context.

**Already works, and is unaffected:** everything that produces a number. All
probability calculations, all 20 distributions, combinatorics, Bayes and
conjugate updating, random experiments, Monte Carlo simulation, scenario
modelling, sensitivity analysis including Sobol indices, risk metrics, the data
lab and its hypothesis tests, Markov chain analysis, persistence, import and
export, and every chart.

Integration adds assistance. It does not add, replace or alter a single
computed value.
