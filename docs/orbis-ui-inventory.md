# Orbis UI inventory (where each Orbis surface lives in the browser)

| Surface | Lives in | Status |
| --- | --- | --- |
| Panel: Ask, Search, Blocking, Notes, Tasks, Workflows, Galaxy, Secrets | `chrome://orbis` (WebUI, `chrome/browser/ui/webui/orbis`, sources `orbis-ui/panel`), shown in the native side panel | Built in; live data from the helper |
| Ad blocking engine (network rules, page filtering, popups, statistics) | Component extension `resources/orbis_extension` (id gcaebck...), hidden from chrome://extensions | Built in as a component |
| New tab page | `chrome://orbis-newtab` (WebUI, sources `orbis-ui/newtab`); Chromium's new tab URL resolves to it (`search.cc`) | Built in (phase 2) |
| Orbis Search results | `chrome://orbis-search` (WebUI, sources `orbis-ui/results`, built from `results.ts`) | Built in (phase 2) |
| Default search URL and its migration | `chromium-orbis-default-search.patch`: `chrome://orbis-search/#q={searchTerms}`; also moves profiles whose default was the old extension-page engine | Done (phase 2) |
| Ctrl+Enter (Orion answer) / Shift+Enter (system browser) | `chromium-orbis-newtab-and-orion.patch` / `chromium-orbis-shift-enter.patch` | Done |
| Sidebar (launcher rail: groups, pin, hide, reorder, icons/labels, compact) | Left rail of `chrome://orbis` (`orbis-ui/panel/sidebar.ts`); the arrangement is kept by the app's `BrowserSidebarStore` through helper channels `sidebar:get/save/reset` | Built in; rows now open their own views (next row) |
| Rail views: Tabs, Tab groups, Media, Controls (`browser:tabs/groups/do` over the Browser Control Layer); Saved pages, Screenshots, Reminders, Clipboard, Whiteboard, Research, Sources, Workspaces (`library:*`, `clipboard:*`, `reminders:*`, `whiteboard:*`, `workspaces:*`, `search-sessions:*`, `research:sources` over the app's own stores) | `orbis-ui/panel/rail/*.js`, bundled into `sidebar.js` (so no new browser resources); helper side `src/helper/browserControl.ts`, `src/helper/panelStores.ts` (`HandlerDeps.stores`, wired in `src/main/index.ts` through `BrowserManager` options) | Built in; UI checked in a headless Chrome against the real helper (`scripts/panel-ui-*.mjs`); Tabs/Groups/Media/Controls checked against an in-memory stand-in for the browser, not yet against Chromium |
| Assistant orb | On `chrome://orbis-newtab` and `chrome://orbis-search` (`orbis-ui/panel/orb.js`): quick Orion prompt on the real `chat:send` channel; "Open the Orbis panel" shows the native side panel (`orbis.openPanel`) | Built in (phase 2); see deferred list below |
| Views restyle (tab strip, toolbar, omnibox popup, menus, dialogs, settings...) | not started | Phase 3 |

## Phase 2 deferred (stated honestly)

- A row whose panel has no implementation is still shown disabled with a tooltip, not faked (none of the rail's rows are in that state now except through their own "not available" message: a view whose store the app did not lend says so). Rows for Bookmarks, History, Downloads, Reading list, Extensions, Profiles, Customize, Privacy and Tracking open Chromium's own page for that feature in a new tab; Orion, Blocking, Notes, Tasks, Workflows, Galaxy and Secrets open the panel's own tab.
- The rail shows in the `chrome://orbis` page (tab or native side panel). The rail can be resized by dragging its right edge (or with the arrow keys on it), groups can be created, renamed, moved and deleted, and rows can be dragged between groups and the pinned list (all in "arrange" mode, all saved through `sidebar:save`), besides pin, hide, up/down, collapse, icons-only/labels and compact. Rows use one icon family (`orbis-ui/panel/rail/icons.js`, Lucide-style line icons, inline).
- Rail view notes: Tabs polls the browser every 2 s only while its view is in front and the page is visible. Favicons come from `chrome://favicon2` (needs the WebUI CSP `img-src chrome://favicon2`, already set); they fall back to a globe. Whiteboard lists boards and their notes/text and can add the page in front as a note; drawing stays in the Orbis window. Saved pages open the saved file with the system (`shell.openPath`), or the original page in a tab; "Screenshots" thumbnails are read only from the library's screenshots folder. Clipboard text that looks like a password or key is masked and only sent by the explicit `clipboard:reveal` call (auto-hidden after 15 s). Research opens `chrome://orbis-search/#q=..&in=orion&s=<id>`. Reminders are tasks that have a time (`TasksStore`). Workspaces open through `browser.openWorkspace` (replace = close the other tabs).
- New capability `zoom.get` (real page zoom) was added to `src/main/chromium/chromiumCapabilities2.ts` for the Controls view; it needs the next Chromium-side run of the capability tests.
- Test-only helper handoff: `?orbis-test-helper=<port>#<token>` is accepted by `orbis-ui/panel/helper.js` only on an `http:` page whose host is exactly `127.0.0.1` (never on `chrome://`), for `scripts/panel-ui-check.mjs`.
- The orb is not drawn over ordinary web pages (a chrome:// page cannot draw over another page; that needs a native overlay or a content script in the component extension). Opening the panel from the orb does not carry the typed prompt across (the quick prompt answers in place).
- The tab context menu (`TabContextMenu.tsx`) belongs to Chromium's native tab strip now (phase 3 restyles it).
