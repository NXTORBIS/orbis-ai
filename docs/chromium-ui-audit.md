## 1. Theming mechanism (applies to everything)
- Views surfaces read `ui::ColorProvider` ids. Chrome ids: `chrome/browser/ui/color/chrome_color_id.h` (e.g. `kColorToolbar`, `kColorNewTabButton*`, `kColorTabStrip*`). Mixers: `chrome/browser/ui/color/chrome_color_mixer.cc`, `material_chrome_color_mixer.cc`, `material_tab_strip_color_mixer.cc`, `tab_strip_color_mixer.cc`, `omnibox_color_mixer.cc`, `material_omnibox_color_mixer.cc`, `material_side_panel_color_mixer.cc`, `new_tab_page_color_mixer.cc`, `material_new_tab_page_color_mixer.cc`, plus `ui/color/*` for cross-platform ids and `chrome/browser/ui/color/win/` for Windows overrides.
- One mixer override (or a BrowserThemeProvider / theme-extension colour set) recolors every Views surface AND WebUI (WebUI pulls the same provider via `chrome://theme/colors.css`, `--color-*` CSS tokens). This is the lowest-risk, functionality-preserving path and is what the existing Orbis patches use.
- Hardcoded colours/paint in Views (bypassing ids) need direct patches; found in tab painting (section 4).

## 4. Tab strip restyle / replacement
Verified structure: `TabStrip` -> `TabContainerImpl` (`tab_container_impl.*`, interface `tab_container.h`) -> `Tab` (`tab.*`) with paint delegated to `TabStyleViews` (`tab_style_views.{h,cc}`; `TabStyleViews::Create` at `tab_style_views.cc:65`) implemented by `HorizontalTabStyleViews` (`horizontal_tab_style_views.cc`: `PaintTab` :346, `PaintTabBackground` :712, `PaintTabBackgroundFill` :730, `GetSeparatorOpacity` :522, `ShouldPaintTabBackgroundColor` :649). Public style API `chrome/browser/ui/tabs/tab_style.h`: `GetStandardHeight`, `GetTabOverlap`, `GetSeparatorCornerRadius`, `GetTopCornerRadius`, `GetBottomCornerRadius`, `kDefaultSelectedTabOpacity=0.75`, declutter constants. Height comes from `LayoutConstant::kTabHeight` (`GetLayoutConstant`, used at horizontal_tab_style_views.cc:92,919; defining file not opened). Geometry: `SkPath GetPath(PathType, ...)` in `TabStyleViews` builds the tab shape.
Options, in increasing cost:
1. **Colour-only** (done in prior commit): mixers in `tab_strip_color_mixer.cc` / `material_tab_strip_color_mixer.cc`, `kColorNewTabButton*`.
2. **Shape restyle**: patch `HorizontalTabStyleViews::GetPath` / corner radii / `GetTabOverlap` and separator painting; no behaviour change, drag/animations untouched (they use `TabStyle` geometry so overlap changes need layout re-check, `tab_strip_layout*.cc` [inferred dependency]).
3. **Full replacement**: no WebUI tab strip exists in 154 (the old chromeOS/touch WebUI tab strip is not present; `resources/tab_strip_internals` is debug only). Replacing means reimplementing `TabContainer` + drag (`views/tabs/dragging/`), groups, hover cards, a11y, controller `browser_tab_strip_controller.*`. High risk; not recommended.
