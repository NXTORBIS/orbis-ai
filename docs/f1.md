# F1 (Orbis Arena)

Formula 1 data and analysis inside Orbis: live timing, session replay, telemetry, tyre strategy, race record, driver and
championship intelligence. Open it with `/f1`, from the command palette (Arena → F1), or from the capability list.

There was no "Orbis Arena" module before this work. F1 is a normal Orbis feature (`f1`, registered the way OrbisEye and
COSMOS are) placed in a new **Arena** command category.

## What each tab does, and where its data comes from

| Tab | What it shows | Provider |
| --- | --- | --- |
| Live | The live leaderboard (gaps, intervals, last/best lap, three sectors with session-best/personal-best marks, tyre, pit stops), a track map with cars, race control, weather, session clock, track status. Also **replay** of a finished session through the same code path, with play/pause/seek/speed. | F1's public live-timing stream (live); the same feeds' recorded archive (replay) |
| Telemetry | One lap (or two overlaid): speed, throttle, brake, gear, RPM, DRS, time delta, track map coloured by speed, lap summaries. | OpenF1 (`car_data`, `location`, `laps`) |
| Strategy | Tyre stints per driver, pit stops and pit-lane time, stint pace and trend, and a what-if strategy calculator. | OpenF1 |
| Race | Classification, position by lap, gap to leader, weather, race control, safety-car/VSC/red-flag periods, overtakes. | OpenF1 |
| Drivers | Season profile, results, points progression, teammate comparison, career, watchlist. | Jolpica-F1 |
| Championship | Points progression, what is still possible under the season's rules, and a what-if scenario builder. | Jolpica-F1 |
| Season / Standings / Results / Timing | Calendar, standings after any round, race classification, every lap of any session. | Jolpica-F1, OpenF1 |
| Sources | Per-provider request counts, failures, last success, last problem; the live stream's state. | — |

No account or API key is needed for any of it.

## The providers, as verified

* **Jolpica-F1** (`https://api.jolpi.ca/ergast/f1/`): calendar, results, sprint results, qualifying, standings, career. Free, keyless.
* **OpenF1** (`https://api.openf1.org/v1/`): sessions, drivers, laps with sector times and speed traps, car telemetry and location, stints,
  pit stops, weather, race control, position, intervals, overtakes, session result, starting grid. **Historical data (2023 on) is free
  and keyless. Its real-time data is a paid plan and is not used.**
* **F1 live-timing stream** (`livetiming.formula1.com/signalrcore`) and its **static archive** (`/static/{year}/…`): the same feeds the sport's own pages and the
  FastF1 project read. **Unofficial.** No key. Orbis speaks the SignalR Core JSON protocol itself (`src/main/f1/live/signalr.ts`), so no separate server
  (such as `f1-livetiming-api`, which wraps the same stream) is needed. It can change without notice.

FastF1 (Python) was evaluated and not used: it would add a Python runtime for the same data Orbis already reads directly.

## Live is not always live

The screen never calls something live that is not:

| State | Meaning |
| --- | --- |
| LIVE | Connected, the session is in progress, and records arrived in the last 20 s. |
| Live, but data is stale | Connected and in progress, but nothing has arrived for over 20 s. |
| Last session (not live) | Connected, but the latest session finished. Its final state is shown. |
| Waiting | Connected; the session has not started. |
| Connection lost | Reconnecting; what is shown is the last data received and may be old. |
| REPLAY | A recorded session. Always labelled, whatever it replays. |

Reconnection backs off 1, 2, 4 … 30 s; a connection silent for 45 s is dropped and re-established.

**What has and has not been verified.** The connection, the full-state snapshot, the merge, replay and telemetry decoding were run against the real feed
and the real archive (the Singapore Grand Prix 2026). *Incremental updates during a running session* were verified by replaying the recorded changes and by
tests with a fake socket, not against a session in progress, because none was running while this was built.

## Calculations (and what they are not)

* **Lap times** are numbers in seconds and are formatted at the edge (`src/shared/f1/time.ts`). A missing time is `null`/"–", never 0.
* **Eligible laps** (best lap, median, stint pace): a recorded time, not an out-lap; for stint pace also not a pit lap and not lap 1.
* **Telemetry distance** is the car's speed integrated over time: an estimate, not a surveyed distance. Two laps are aligned by *fraction* of the lap.
  The **delta** is the time difference at the same fraction (positive = the other lap was slower there).
* **Tyre trend** is the slope of lap time against tyre age (least squares, at least 5 laps). It mixes wear, fuel burn-off, traffic and conditions. It describes
  what happened; it does not measure wear.
* **Strategy what-if** adds up its stated assumptions only (fresh pace + wear per lap, pit-lane loss per stop). It does not model fuel, traffic, track
  evolution or safety cars. It is labelled hypothetical.
* **Championship rules** are versioned by season (`src/shared/f1/championship.ts`): the points scale, the fastest-lap point (2019–2024), sprints
  (2021 on). A season with no recorded rules is refused. "Still possible" is points-based: a contender is out of reach only if even every remaining
  maximum cannot level the leader's points today. Ties are ordered by wins, then second places, and listed as unresolved when those cannot separate them.
* **Teammate comparison** counts only rounds where both drove for the same team; a retirement is not a comparable finish.
* **Safety-car / VSC / red-flag periods** come from race-control messages only (`VSC DEPLOYED` … `VSC ENDING`, `SAFETY CAR DEPLOYED` …, `RED FLAG`).

## Caching, limits and failure

`src/main/f1/service.ts`: one request per address at a time; answers reused within a freshness window (a finished lap's telemetry for a day; a
standing for minutes); a minimum spacing between requests per provider; a provider's `429`/`Retry-After` is honoured; a failed refresh returns the last
good answer marked **stale** with its own retrieval time; an answer with nothing usable is not cached. OpenF1's `404` ("no results") is read as "nothing".

## Privacy

Notes, the watchlist and saved lap comparisons are kept in this window's local storage only. Nothing is sent anywhere. Exports are CSV files made
in the window from what is on screen.

## Intelligence screens (added after the first slice)

| Where | What | Notes |
| --- | --- | --- |
| Live → leaderboard | Find a driver or team, compact rows, speed-trap column, click a driver to focus (best/last lap, speed traps, tyre history), full screen, CSV export, a **timing events** list (pit in/out, retirement, lead change, session-best lap) built only from what changes while you watch | Nothing is back-filled |
| Drivers → profile | Last five results, consistency (median, spread, places gained, biggest gain), percentile among the season's regular drivers by finishing position, points per race and grid | A percentile needs five placed drivers; ties count half |
| Teams | Share of the team's points by driver, and a team-against-team duel (points, better best finish per round, average grid) | Rounds with no classified car on either side are not counted |
| Championship | Points behind the leader and championship position through the season, drivers or constructors | Built from each round's own points |
| History | The champion, runner-up and constructors' champion of any season; "every champion since 1950" (77 small requests, paced, resumable); titles; a what-data-exists-for-this-era table | Points systems differ by era, so only wins-as-a-share-of-races is comparable |
| Strategy | Compounds across the session, each stint's trend carried forward with its spread, pit-lane time by team and unusually slow stops, a sensitivity table for the what-if, saved plans | A projection is the trend's own spread, not a prediction; a slow stop is flagged, not judged |

## Known limits

* No "live" claim is made without a running session; see above.
* Telemetry is fetched one lap at a time (a provider and size limit).
* Circuit outlines come from one real lap's position readings. Corner numbers are estimates and may not match the official ones; there are no sector boundaries.
* Free OpenF1 history starts in 2023; Jolpica goes back much further (results, standings, fastest laps from 2004), but lap timing and telemetry do not.
* Reports can be saved as HTML or as a PDF Orbis writes into Downloads. Not built: tyre-set identity, a team-radio transcript.
* Notes and saved lap comparisons are still kept in this window's storage; the watchlist and alert switches are per profile.
